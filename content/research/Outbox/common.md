## Outbox 패턴 용어

Outbox 패턴 자체를 설명하는 용어입니다.

| 용어 | 의미 |
| --- | --- |
| Sender | 업무 데이터를 변경하고, 같은 트랜잭션에서 발행할 메시지를 기록하는 서비스 |
| Outbox / Message Outbox | 발행할 메시지를 영속적으로 보관하는 저장소. 관계형 DB에서는 보통 테이블 |
| Outbox Record / Entry | Outbox에 저장된 개별 메시지 한 건 |
| Message Relay | Outbox의 메시지를 읽어 브로커로 전달하는 구성요소 |
| Polling Publisher | Outbox를 주기적으로 조회해 메시지를 발행하는 릴레이 구현 방식 |
| Transaction Log Tailing | DB 트랜잭션 로그에서 Outbox의 변경을 읽어 발행하는 릴레이 구현 방식 |

## 점유 기반 폴링 구현 용어

아래는 이 연구에서 다루는 점유 기반 폴링 구현의 코드 명칭입니다. Outbox 패턴 전체에 공통으로 요구되는 명칭은 아니며, 다른 라이브러리나 구현에서는 이름이 달라질 수 있습니다.

| 코드 용어 | 의미 |
| --- | --- |
| `Append` | Outbox에 이벤트 기록 |
| `ClaimDue` | 발행 또는 재시도 시간이 된 이벤트의 처리 권한 확보 |
| `Lease` | 유효 시간이 있는 처리 권한 |
| `Lease Token` | 현재 점유를 식별하고 상태 변경 권한을 확인하는 값 |
| `MarkPublished` | 이벤트를 발행 완료로 기록 |
| `ScheduleRetry` | 다음 발행 시도 예약 |
| `ErrLeaseLost` | 점유 권한이 유효하지 않아 상태를 변경할 수 없음을 나타내는 오류 |
